# app2email setup

## No account yet: an agent starts it, the person finishes it

Management MCP server `https://api.app2email.com/mcp/manage` (https://www.app2email.com/docs/api/agents). No previous human sign-up is required.

1. Call `create_account` with `contact_email` (no key). It returns `signup_id`, `management_key`, `onboarding_link` and `message`.
2. Give the person `onboarding_link`: they confirm the e-mail, connect their WhatsApp number and choose a plan. Nothing can be sent before that. `get_account_status` says what is still needed.
3. Pass the `management_key` as `Authorization: Bearer <management_key>` on every later call.
4. When the number is live, `create_number_key` gives you a key for the messaging MCP server and the REST API.

## What the person does (an agent cannot)

1. Connect the WhatsApp Business number on https://www.app2email.com (Embedded Signup with Meta; an existing WhatsApp Business app number keeps working on the phone, this is called coexistence).
2. Pick a paid plan: the API needs one (`403 plan_not_allowed` otherwise).
3. Create an API key on https://www.app2email.com/dashboard/apikey. Choose scopes for the job, an expiry, optionally an IP allow-list. A **sandbox** key simulates sends (nothing reaches a phone, nothing is counted): use one while building. A key can carry a **daily cap** and an **approval threshold** (sends to more numbers than the threshold wait for a human OK on the dashboard).
4. Give the agent the key and the number through the environment: `APP2EMAIL_API_KEY`, `APP2EMAIL_NUMBER`.

## Scopes

A key has scopes: `messages:send` (send, media upload, cancel a broadcast, conversation owner, approvals), `messages:read` (messages, conversations, broadcasts, usage, stats, templates, request log, contacts, stored media), `dnc:manage` (Do Not Call list, compliance export), `webhooks:manage`, `templates:manage` (templates and flows: create, edit, delete, archive, insights; each change applies to every number of the WhatsApp Business Account), `settings:manage` (auto reply, email forwarding, opt-ins, the number's settings), `contacts:manage` (contacts, segments, consent records), `calls:manage` (WhatsApp Calling), `bookings:manage` (appointment bookings, the booking settings, sending a Flow; the booking reads also work with `messages:read`), `submissions:manage` (Submit-Info: forms, submissions, the inbox team, automations and connections), `tickets:manage` (event tickets: events, ticket types, orders, refunds, tickets, check-in, promo codes), or `*` for full access. The Default key (the key made before keys with permissions existed) has `messages:send`, `messages:read`, `dnc:manage` and `webhooks:manage` only - creating templates and changing settings need a key created with Full access. A call the key may not make answers 403 `insufficient_scope`. A key can also be limited to some IP addresses, or expire. `GET /v1/{number}/me` checks a key and shows its name, scopes and limits.

Ask for the smallest set: a support agent needs `messages:read` and `messages:send`; a CRM sync needs `contacts:manage`; opt-out handling needs `dnc:manage`; nothing needs `*`.

## Connect a client

- **MCP (Claude Code, Claude, Cursor, VS Code, Codex, OpenClaw):** `https://api.app2email.com/mcp` (Streamable HTTP) with `Authorization: Bearer YOUR_API_KEY`; reads are marked read-only, every send or change destructive. Claude Code: `claude mcp add --transport http app2email https://api.app2email.com/mcp --header "Authorization: Bearer YOUR_API_KEY"`. Every client: https://www.app2email.com/docs/api/mcp
- **OpenClaw channel (the agent answers WhatsApp messages as they arrive):** `openclaw plugins install clawhub:@app2email/openclaw-whatsapp`, then `channels.app2email-whatsapp.apiKey` and `.number`.
- **n8n:** community node `n8n-nodes-app2email` (credential: API key + number). **Zapier:** the app2email app (custom auth: key + number). **Make:** import `https://api.app2email.com/v1/openapi.json`. **Power Automate:** custom connector from `https://api.app2email.com/v1/swagger2.json`.
- **Code:** `npm install app2email-api` / `pip install app2email-api`, or plain HTTP with the Bearer header.

## Check it works

```
curl -H "Authorization: Bearer $APP2EMAIL_API_KEY" https://api.app2email.com/v1/$APP2EMAIL_NUMBER/me
```

`key_valid: true`, `service_status: "LIVE"` and the scopes you expect. Then `GET /templates` and a `POST /messages` with `"dry_run": true`.

## Limits to tell the user about

- Free-form replies: `"type": "text" | "image" | "video" | "document"` sends a normal message (not a template) to one number, but only within 24 hours of that contact's last message to your number (app2email stops 15 minutes early; `window_closes_at` in the answer is the exact time, and `window_open` in `GET /v1/{number}/conversations` says whether it is open now). `text`: `{"body": "...", "preview_url": false}`. `image`, `video`, `document`: `link`, base64 `data` (with `filename`) or a media `id`, plus an optional `caption`. Optional `reply_to` quotes one of the contact's messages (a `wamid.` id).
- Rate limit: every call counts against its key (calls without a key: against the IP address). Each answer has the headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (seconds until full again) and `X-RateLimit-Policy`. Over the limit: 429 `rate_limited` with a `Retry-After` header and `error.retry_after_seconds`. Wait, then send again (`limits.rate_limit_mode` in GET /me is `enforce`).
- Several recipients: put a list of numbers in `to`, separated by commas (`"61412345678,61498765432"`), or as a JSON array. Each number gets its own message with the same values; duplicates are sent once. The answer then has one entry per number in `results`, and the HTTP status is 200 when all were accepted, 207 when some were. The most numbers per request is the number's broadcast limit (as on the Broadcast page, up to 1000).
- Media: image, video or document as `link` (app2email downloads it), base64 `data` in the request, or a WhatsApp media `id`. Leave the header component out to send the template's own sample image, video or document. WhatsApp limits: images (JPG/PNG) 5 MB, videos (MP4/3GP) 16 MB, documents 100 MB. Requests can be up to 140 MB (a 100 MB file as base64).
- Plans: every call, reading as well as sending, needs a paid plan (Standard, Professional, Team, Agency or Agent/Developer; 403 `plan_not_allowed`) and a LIVE service (403 `service_not_live`).
