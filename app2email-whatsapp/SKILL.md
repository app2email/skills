# app2email WhatsApp

app2email connects a business's own WhatsApp number (official WhatsApp Business Cloud API, the customer owns the number and pays Meta directly) to email, to automations and to agents. This skill is for an agent that sends or reads WhatsApp messages through the REST API `https://api.app2email.com/v1/{number}/...`, through the MCP server `https://api.app2email.com/mcp` (189 tools: https://www.app2email.com/docs/api/mcp), or through the SDKs (`app2email-api` on npm and PyPI).

## Setup

- Base URL: `https://api.app2email.com/v1/YOUR_NUMBER` where `YOUR_NUMBER` is the WhatsApp number you send from, country code first, digits only.
- Auth: `Authorization: Bearer YOUR_API_KEY`. Keys come from https://www.app2email.com/dashboard/apikey and are shown once. Keep them in the environment (`APP2EMAIL_API_KEY`, `APP2EMAIL_NUMBER`).
- First call: `GET /me` (is the key valid, which scopes, which plan, the limits). If it fails, stop and tell the user.
- Reference: https://www.app2email.com/docs/api (one page per call, add `.md` for Markdown), errors https://www.app2email.com/docs/api/errors#<code>, webhooks https://www.app2email.com/docs/api/webhooks. For agents: https://www.app2email.com/llms.txt, https://www.app2email.com/docs-api.md (everything in one file), OpenAPI `https://api.app2email.com/v1/openapi.json`.

A key has scopes: `messages:send` (send, media upload, cancel a broadcast, conversation owner, approvals), `messages:read` (messages, conversations, broadcasts, usage, stats, templates, request log, contacts, stored media), `dnc:manage` (Do Not Call list, compliance export), `webhooks:manage`, `templates:manage` (templates and flows: create, edit, delete, archive, insights; each change applies to every number of the WhatsApp Business Account), `settings:manage` (auto reply, email forwarding, opt-ins, the number's settings), `contacts:manage` (contacts, segments, consent records), `calls:manage` (WhatsApp Calling), `bookings:manage` (appointment bookings, the booking settings, sending a Flow; the booking reads also work with `messages:read`), `submissions:manage` (Submit-Info: forms, submissions, the inbox team, automations and connections), `tickets:manage` (event tickets: events, ticket types, orders, refunds, tickets, check-in, promo codes), or `*` for full access. The Default key (the key made before keys with permissions existed) has `messages:send`, `messages:read`, `dnc:manage` and `webhooks:manage` only - creating templates and changing settings need a key created with Full access. A call the key may not make answers 403 `insufficient_scope`. A key can also be limited to some IP addresses, or expire. `GET /v1/{number}/me` checks a key and shows its name, scopes and limits.

## Start here

1. `GET /me` checks the key.
2. `GET /templates` lists the approved templates, each with the values it needs and a complete `example_request`.
3. `GET /conversations/{contact}/messages` (or `GET /conversations`) tells you whether the contact's reply window is open (`window_open`).
4. `POST /messages` with `"dry_run": true` checks everything and sends nothing.
5. `POST /messages` for real, with an `Idempotency-Key` header. Then `GET /messages/{message_id}` or a webhook reports delivery.

## Which message to send

| Situation | Send |
| --- | --- |
| Starting a conversation, or `window_open` is false | an approved template: `"type": "template"` |
| The reply window is open (the contact wrote within 24 hours) | a free-form message, one contact per call: `"type": "text"` / `image` / `video` / `document` / `audio` (`"voice": true`: a voice note) / `sticker` / `location` / `contacts` / `reaction` (each counts as one message), or a template |
| Buttons, a menu, cards, a form, a location or the contact's number | `"type": "interactive"`: `button`, `list`, `cta_url`, `carousel`, `flow`, `location_request_message`, `request_contact_info` |
| Show that you read it, or that you are typing | `POST /messages/read` with the `message_id` (`"typing": true` for the typing indicator). Free: not counted, no window |
| The same or a personalised message to many numbers | a template with `to` as a list, or `recipients` with per-number values, or `segment` |
| A big list, or the client stops waiting after about 30 seconds | add `"background": true`, then follow `GET /broadcasts/{code}` |
| Later | a template with `"send_at"` (ISO 8601 with a time zone, 1 minute to 29 days ahead) |
| The person asks for a human | `PUT /conversations/{contact}/owner` with `"owner": "human"`, a reason and a summary (see app2email-agent-handoff) |

## Guardrails (read before any send)

- CANNOT send a free-form message (text, image, video, document, buttons) to a contact whose 24 hour window is closed. `window_open: false` or `422 outside_24h_window` means: send an APPROVED template instead, or stop.
- CANNOT send marketing to a number on the Do Not Call list (the API refuses with `403 recipient_opted_out`) or to a person who has not consented to marketing. Utility messages (order updates, reminders the person asked for) do not need marketing consent.
- CANNOT connect a WhatsApp number or pay for a plan: a person does that. An agent can start an account for a person with the Management MCP server (`create_account`, see app2email-setup); otherwise ask the user for the number and a key.
- CANNOT read messages of other numbers: a key belongs to one number.
- Every send reaches a real person's phone and counts against the customer's monthly plan (outgoing WhatsApp messages and outgoing emails together). Confirm the recipients and the content with the user unless they already told you to send; use `dry_run: true` first for template sends; use an `Idempotency-Key` so a retry never sends twice.
- Never put the API key in a message, a log, a web page or a reply to the user.
- When the person asks for a human, stop automating that contact: hand the conversation over (see the agent handoff skill) and say so.

## Errors

Every failed call returns `{ "success": false, "request_id": "...", "error": { "code", "message", "how_to_fix", ... } }`. Read `how_to_fix`; copy `example_request` when it is given; wait `Retry-After` seconds on 429; quote `request_id` to the user when you cannot fix it. The full list is in [references/errors.md](references/errors.md).

## Facts worth remembering

- Free-form replies: `"type": "text" | "image" | "video" | "document"` sends a normal message (not a template) to one number, but only within 24 hours of that contact's last message to your number (app2email stops 15 minutes early; `window_closes_at` in the answer is the exact time, and `window_open` in `GET /v1/{number}/conversations` says whether it is open now). `text`: `{"body": "...", "preview_url": false}`. `image`, `video`, `document`: `link`, base64 `data` (with `filename`) or a media `id`, plus an optional `caption`. Optional `reply_to` quotes one of the contact's messages (a `wamid.` id).
- Rate limit: every call counts against its key (calls without a key: against the IP address). Each answer has the headers `X-RateLimit-Limit`, `X-RateLimit-Remaining`, `X-RateLimit-Reset` (seconds until full again) and `X-RateLimit-Policy`. Over the limit: 429 `rate_limited` with a `Retry-After` header and `error.retry_after_seconds`. Wait, then send again (`limits.rate_limit_mode` in GET /me is `enforce`).
- Several recipients: put a list of numbers in `to`, separated by commas (`"61412345678,61498765432"`), or as a JSON array. Each number gets its own message with the same values; duplicates are sent once. The answer then has one entry per number in `results`, and the HTTP status is 200 when all were accepted, 207 when some were. The most numbers per request is the number's broadcast limit (as on the Broadcast page, up to 1000).
- Media: image, video or document as `link` (app2email downloads it), base64 `data` in the request, or a WhatsApp media `id`. Leave the header component out to send the template's own sample image, video or document. WhatsApp limits: images (JPG/PNG) 5 MB, videos (MP4/3GP) 16 MB, documents 100 MB. Requests can be up to 140 MB (a 100 MB file as base64).
- Plans: every call, reading as well as sending, needs a paid plan (Standard, Professional, Team, Agency or Agent/Developer; 403 `plan_not_allowed`) and a LIVE service (403 `service_not_live`).
